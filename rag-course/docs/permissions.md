# 权限体系说明与操作手册

> 本文档说明本系统的权限模型、内容划分原则，以及用户权限的具体操作。

## 1. 权限模型（当前实现）

- **文档**：入库时打一个 `access` 标签（`store.py` 的 `FILE_ACCESS` 映射，如 `"all"` / `"finance"`）；
- **用户**：`users` 表的 `groups` 字段存权限组数组（如 `["all"]`、`["all", "finance"]`）；
- **检索**：Chroma `where access $in 用户groups`——用户能看什么，由"文档标签是否在他的组里"决定；
- **实时生效**：每次请求都从数据库读 `groups`，改权限**无需重新登录**，下一次请求即生效；
- **服务端判定**：客户端只能报身份（token），不能自己声明权限。

## 2. 内容划分：三档模型（建议）

| 档位 | 标签 | 放什么 | 谁能看 |
| --- | --- | --- | --- |
| 全员公开 | `all` | 员工手册、考勤制度、报销流程等通用制度 | 所有用户 |
| 部门级 | `dept_财务`、`dept_HR`、`dept_研发`… | 部门内部流程、专业制度 | 对应部门成员 |
| 机密级 | `executive` | 高管薪酬、战略规划、未公开决策 | 仅高管/授权者 |

### 划分原则

1. **最小权限**：一份文档标它"必须知道的人"的最小集合，不是"可以知道"的集合——宁严勿松；
2. **按内容敏感度**：是否含个人隐私（工资）、财务数据、未公开信息 → 敏感度越高档位越高；
3. **按归属**：这个流程是谁的？（报销→财务、招聘→HR）→ 归那个部门组。

### 交叉可见怎么办

一份文档既给财务又给 HR 看 → 不要给文档打多个标签，而是**建一个覆盖两组的新组**（如 `dept_财务HR`）或归到两者共同的上层组。保持"**文档一个标签、用户多个组**"的结构最干净。

### 用户侧配置

每个用户的 `groups` = `["all"]` + 所属部门组 + `admin`（管理员）：

| 角色 | groups 示例 |
| --- | --- |
| 普通员工 | `["all"]` |
| 财务 | `["all", "dept_财务"]` |
| HR | `["all", "dept_HR"]` |
| 高管 | `["all", "executive"]` |
| 管理员 | `["all", "admin"]` |

## 3. 用户权限操作

以下均为 CLI（管理通道，需要能登上服务器/访问数据库的人执行）：

### 查看当前用户

```bash
python app/auth.py list
```

### 修改权限组

```bash
python app/auth.py set-groups
```

交互式输入：用户名 → 新权限组（逗号分隔，如 `all,finance`）。

要点：

- 改完**立即生效**，无需重新登录；
- 会记录一条 `group_change` 安全事件（`python app/auth.py security-log` 可查）——改权限和改密码一样属于敏感操作；
- 修改时必须**保留 `all`**，否则连全员文档都看不到。

### 创建用户

```bash
python app/auth.py add-user
```

### 修改密码

```bash
python app/auth.py change-password
```

## 4. 给新文档划分权限的完整流程

以一份"HR 薪酬细则"为例：

```text
1. 文档放进 data/sample/
2. 打开 store.py，在 FILE_ACCESS 加一行：
      "薪酬细则.docx": "dept_HR"
3. 重建索引（admin 登录 → 侧边栏"重建索引"）
4. 给 HR 用户加组：python app/auth.py set-groups → 用户名 → all,dept_HR
5. 验证：HR 用户能问到，普通员工问不到
```

## 5. 生产化方向

- 当前 `FILE_ACCESS` 是**硬编码字典**——每加一份文档都要改代码。生产化做法：
  - 上传文档时指定权限标签（上传接口带 `access` 参数，存进文档元数据）；
  - 或按文档目录/密级自动打标；
- 改权限目前是 CLI（管理通道）；未来可做"管理员 API 改权限"（需先有用户管理接口 + admin 校验）；
- 权限组命名建议统一用 `dept_` 前缀，避免和 `all`、`admin` 混淆。

## 6. 常见问题

| 问题 | 排查 |
| --- | --- |
| 改了权限没生效 | 权限实时生效；确认改对用户名；确认 `groups` 里保留了 `all` |
| 文档标签改了，检索还是旧结果 | 改 `FILE_ACCESS` 后必须重建索引 |
| 用户看不到刚上传的文档 | 检查文档 `access` 标签是否在他的 `groups` 里；重建索引后生效 |
| 普通用户能调重建索引吗 | 不能——`/api/documents/rebuild` 需要 `admin` 权限（403） |
| 忘记密码/想重置 | `python app/auth.py change-password`（CLI 不需要旧密码） |
